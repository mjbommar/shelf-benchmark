QUESTION: Are sparse baselines (TF-IDF, BM25) unfairly advantaged over dense
          neural embeddings in the SHELF benchmark?

ANSWER:   NO - The comparison is fair and follows established best practices.

================================================================================
EVIDENCE
================================================================================

1. HYPERPARAMETERS (All use standard defaults)
   ✓ TF-IDF:  sklearn documentation (bigrams, sublinear TF, 256 SVD)
   ✓ BM25:    Okapi defaults k1=1.5, b=0.75 (Elasticsearch, Lucene)
   ✓ Dense:   HuggingFace pretrained, L2-normalized
   ✓ No corpus-specific tuning on SHELF

2. PREPROCESSING (Inherent differences, not bias)
   - Tokenization:  Sparse=regex/whitespace, Dense=WordPiece/SentencePiece
   - OOV handling:  Sparse=drop, Dense=subword decomposition
   - Normalization: Both use L2-norm for cosine similarity

3. LITERATURE SUPPORT
   - MTEB: Uses BM25 baseline with standard parameters
   - BEIR: Uses TF-IDF with bigrams as baseline
   - E5 paper: "First model to beat BM25" (acknowledges BM25 strength)
   - ACM SIGIR 2025: "Sparse and dense are complementary"

4. BALANCED TRADE-OFFS
   Sparse advantages:  Exact match, bigrams, large vocab, no GPU
   Sparse disadvantages: No semantics, no context
   Dense advantages:  Semantics, context, OOV handling, pretraining
   Dense disadvantages: Compute cost, domain mismatch
